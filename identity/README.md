# Phase 14 — Identity & advanced boot hardening

The master manual wants passkeys, FIDO2, biometrics, and a matured boot
chain (Secure Boot enrolment, TPM measured boot, a signed/locked
bootloader). On a **live ISO** that splits cleanly in two:

## What's real here

`chakra-identity` (`identity/bin/`, in the **System Maintenance** menu) —
one tool that shows the account's authentication posture and enrols the
credentials you *can* set up in a live session:

| Section | What it reports / does |
|---|---|
| Login | password set / locked / none; autologin on? |
| Hardware key (FIDO2/U2F) | registered credentials; whether sudo requires one. `add-key` runs `pamu2fcfg`, `require-key` / `require-password` toggle the `pam_u2f.so` line in `/etc/pam.d/sudo` (with a backup). |
| Fingerprint | reader present? enrolled prints. `add-fingerprint` runs `fprintd-enroll` if a reader is claimed. |
| SSH | service state, whether password auth is allowed. |
| sudo | any `NOPASSWD` rules (flagged). |
| Boot chain | Secure Boot state (`mokutil`), TPM presence, firmware type. |

`--json` for scripting. Packages added: `libpam-u2f`, `fprintd`,
`libpam-fprintd`, `fido2-tools` (`libfido2` was already in).

Enrolments in a live session don't persist — `chakra-snapshot save
identity` (Phase 11) keeps `~/.config/Yubico/` and the PAM edits, or wait
for an installed system.

## What's deferred to the installer

- **Secure Boot key enrolment** — needs a persistent EFI partition and
  the ability to enrol MOK / platform keys; a self-built hybrid ISO
  can't meaningfully do this.
- **TPM measured boot / sealing secrets to PCRs** — needs a real,
  unchanging boot chain to measure.
- **A signed and locked bootloader** — the ISO's GRUB is regenerated by
  `grub-mkrescue` each build; locking it is an installed-system concern.
- **Passkeys** are WebAuthn — browser-side. Firefox (bundled) already
  supports them; there is nothing OS-level for Chakra to build.

This is the same honest deferral as Secure Boot in Phase 5's notes and
persistence in Phase 11 — the installer is the missing prerequisite, and
it isn't a numbered phase yet.
